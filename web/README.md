# Body Build · PWA

Самостоятельная веб-версия на React + TypeScript. Сборка рассчитана на Safari
iOS 16.4+ и современные браузеры. Серверная часть, аккаунт и ключи API не нужны.
Android-приложение остаётся отдельным приложением.

## Готовая сборка

`dist/` — статические файлы для размещения. `body-build-pwa.zip` в этой папке
содержит файлы сборки в корне архива. Распакуйте их в корень HTTPS-сайта или
в отдельную папку сайта. Для папки адрес должен заканчиваться `/`.
Опубликованная версия: **https://body-build-gadxx.pages.dev/**.
Хостинг — Cloudflare Pages (Direct Upload), без серверных функций и платных ресурсов.

### Автоматическое обновление Cloudflare Pages

Workflow `.github/workflows/deploy-pages.yml` запускается при каждом push в `main`
или вручную через GitHub → Actions → Deploy Body Build → Run workflow.
Он выполняет `npm ci`, тесты и сборку, публикует `dist` в существующий проект
`body-build-gadxx`, затем проверяет commit в публичном `release.json`.
Ошибки тестов или сборки останавливают публикацию. Pull request и другие ветки
не получают доступ к production-деплою. Одновременно выполняется одна публикация.

Однократная настройка владельцем аккаунта:

1. В Cloudflare создайте API Token с единственным правом
   **Account → Cloudflare Pages → Edit**, ограниченный аккаунтом этого проекта.
   Это право относится ко всем Pages-проектам выбранного аккаунта, не только к одному сайту.
2. В GitHub-репозитории откройте Settings → Secrets and variables → Actions
   и сохраните токен как repository secret `CLOUDFLARE_API_TOKEN`.
   Не вставляйте токен в чат, код или журналы. Account ID в workflow не является секретом.
3. Запустите workflow и убедитесь, что шаг Verify public deployment завершился успешно.

До добавления секрета автопубликация не работает. Платные услуги не требуются,
но сборки используют квоту GitHub Actions приватного репозитория; не подключайте
платный перерасход. При истечении или отзыве токена замените GitHub secret.

Обновляется именно веб-версия из `web/`, а не Android APK. Изменения Kotlin-каталога
перед push экспортируйте командой `npm run sync:catalog` из `web` и включайте
изменённые веб-данные в коммит. Логику Android и React нужно изменять отдельно.

Открытая тренировка не перезагружается принудительно. После публикации дайте
приложению загрузить обновление онлайн, затем закройте все его вкладки/окна
и откройте снова. Записи в IndexedDB сохраняются; данные сайта очищать не нужно.

### Ручное обновление (резервный способ)

Проект в Cloudflare: `body-build-gadxx`. Используйте постоянный адрес выше:
данные браузера привязаны к адресу сайта, на preview-адресах будет другое хранилище.

1. В папке `web` выполните `npm ci`, `npm test`, `npm run build`.
2. В Cloudflare откройте Workers & Pages → `body-build-gadxx` → Create deployment.
3. Выберите Production и загрузите содержимое свежей папки `web/dist`
   (или новый ZIP, где `index.html` находится в корне).
4. Дождитесь завершения загрузки и нажмите Deploy site.
5. Проверьте постоянный адрес. Для обновления установленной PWA закройте
   все её окна после завершения тренировки и откройте приложение снова.

Встроенная Git-интеграция Cloudflare не используется: автодеплой выполняет GitHub Actions.
Готовый ZIP не пересоздаётся командой `npm run build`; для следующих публикаций
используйте свежий `dist`, а не старый архив. Приватность GitHub-репозитория
не ограничивает доступ к сайту: приложение доступно по публичному URL,
а записи тренировок остаются локальными в IndexedDB. Делайте резервные копии
через профиль; серверного хранения и синхронизации нет.

Не открывайте `index.html` двойным щелчком через `file://`: модули, IndexedDB
и service worker требуют веб-сервер. HTTP на IP компьютера в локальной сети
не подходит для установки и полноценного офлайн-режима на iPhone — нужен HTTPS.

### Посмотреть на компьютере

```bash
cd web
npm ci
npm run build
npm run preview
```

Откройте `http://localhost:4173`. Исключение для localhost позволяет проверить
service worker без HTTPS на том же компьютере. Сервер предварительного просмотра
предназначен для разработки, не для публичного хостинга.

### Установить на iPhone после размещения

1. Откройте HTTPS-адрес в Safari.
2. «Поделиться» → «На экран Домой».
3. Включите «Открывать как веб-приложение», если переключатель предлагается.
4. Запустите приложение с главного экрана. При первом запуске нужен интернет:
   дождитесь отметки «Приложение и фото доступны офлайн».
5. Начинайте вести дневник в установленном приложении. Если записи уже сделаны
   в Safari, сохраните копию в профиле и восстановите её в установленной PWA.

[Инструкция Apple](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios).
Safari и приложение на главном экране могут иметь отдельные данные:
[WebKit, политика переноса хранилища](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/).

## Возможности

- 133 упражнения и 258 встроенных фотографий; поиск, фильтры, любимые/исключённые.
- Генерация full body/сплита, ограничения по времени, оборудованию, опыту и
  приоритетам. Сохранение нескольких программ, замены с повторным расчётом.
- Запуск по программе или свободная тренировка, добавление подходов на ходу,
  пропуски, отмена, ручное завершение свободной тренировки.
- Вес и повторы для каждого подхода из последнего выполнения упражнения;
  кнопки ±1, отдых и общее время занятия.
- История, выбор занятий галочками, анализ фактической нагрузки, тоннаж,
  графики и сравнение за последнее выполнение / неделю / месяц.
- Редактирование роста и веса без изменения старых подходов.
- Экспорт и восстановление JSON-копии с проверкой структуры. Восстановление
  заменяет данные веб-версии после подтверждения.

## Хранение и ограничения iOS

Записи сохраняются в IndexedDB после каждого подтверждённого действия.
Очередь и таймеры восстанавливаются после перезапуска; таймер основан на
абсолютном времени, а не на работе JS в фоне. Несохранённый ввод поля ещё не
является выполненным подходом. Фоновый звук и уведомления не реализованы:
при блокировке iOS может приостановить JavaScript.

Профиль → «Сохранить копию» создаёт локальный JSON-файл. Храните копии вне
браузера: очистка данных сайта или удаление данных системой может убрать
историю. Приложение запрашивает persistent storage, но браузер может отказать.
Не используйте приватный режим для постоянного дневника.
[Политика хранения WebKit](https://webkit.org/blog/14403/updates-to-storage-policy/).

**Синхронизации и автоматического переноса Android → PWA нет.** Формат JSON-копии
PWA версионирован, но не является экспортом Android/Room. Серверы, трекеры,
аналитика и загрузка пользовательских записей в сеть отсутствуют.

Нагрузка и силовой индекс — условные ориентиры, не медицинские измерения.
Каталог содержит несколько явно подписанных близких вариантов фотографий.

## Разработка и обновление

```bash
npm ci
npm run dev
npm test
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

Node.js 22.12+; зависимости зафиксированы в `package-lock.json`.
Генератор работает в Web Worker, не блокируя интерфейс. Его правила перенесены
из Kotlin; 11 контрольных наборов сравниваются с результатом Android-генератора.
Для обновления исходных каталогов из Kotlin (из `web/`):

```bash
npm run sync:catalog
cd ..
./gradlew :domain:generator:exportWebFixtures
cd web
npm test
npm run build
```

Для обычной веб-сборки Kotlin/Android SDK не нужны: JSON и медиа уже включены.
`scripts/sync-media.mjs` копирует существующие фотографии и подписи вариантов;
источник — [Free Exercise DB](https://github.com/yuhonas/free-exercise-db),
лицензия включена в `public/exercise-photos/LICENSE.txt`.

Service worker кеширует всю сборку и медиа атомарно. При неполной загрузке
он не активируется. Новая версия не перезагружает активную тренировку:
установка обновления ожидает закрытия старых окон. Обновления кеша не трогают
IndexedDB. На хостинге задайте `Cache-Control: no-cache` для `index.html`,
`sw.js`, `catalog.json`, `media.json` и manifest. Можно кешировать файлы с хешами
в `assets/` надолго. Публикуйте сборку целиком, не отдельные изменённые файлы.

## Что проверено

- 20 unit-тестов: каталог, 11 Android golden cases, ограничения генератора,
  сессии, прошлые подходы, нагрузка, JSON, конфликты записей из разных вкладок.
- Браузерные сценарии в Chromium и WebKit с мобильным viewport: запись,
  перезагрузка, история, анализ, параметры, подстановка прошлого подхода,
  генерация, фотографии и офлайн-перезагрузка при полностью остановленном сервере.
- Просмотр мобильных скриншотов. Настоящий iPhone, установка через системное
  меню Safari и работа под длительной блокировкой требуют проверки на устройстве.

WebKit на Linux в тестах не равен Safari на физическом iPhone. На этой Arch Linux
машине для тестового WebKit потребовались локальные библиотеки Ubuntu в кеше
браузера; на поддерживаемой Ubuntu достаточно `npx playwright install --with-deps`.
